# 项目状态

当前为可运行的第一阶段 MVP，提供通用原始 CAN 工作台与独立实验性物理量视图。

## 已实现

- Mock / MX+ Windows COM / 原始 Replay Transport；有界采集、错误计数、批量 WS。
- ID 聚合、虚拟化表格、字节变化、搜索排序、暂停展示及原始字节曲线。
- 原始 CAN 和诊断响应分别记录，SQLite 会话索引、NDJSON 导出、离线回放。
- 英文 UI，System / Light / Dark 图标切换；Generic 与实验性 BYD 配置独立于通道参数。
- 固定四项电池 DID 与可选 10 个候选分组，共 44 项白名单；无任意发送接口。
- 电池示意图、分组电压区间与压差、候选温度 A/B、物理量趋势、人工动作标记及离线统计。

## 验证状态

自动化检查覆盖 Mock、固定合成响应、错误输入、生命周期、记录与回放。短时硬件路径取得过原始帧和诊断响应，但不等于长期稳定性、混合 ID 覆盖或换算准确性认证。公开仓库不包含任何操作者实车会话、读数、设备身份或测试时间线。

## 已知限制

- Windows Bluetooth COM 可能返回 121；重新配对或重连效果不确定，根因未确认。
- 原始 MX+ STM 16 为有间隙采样；高负载完整监听曾遇 BUFFER FULL，不承诺无损。
- DID 核心与分组顺序读取；分组较慢，不能分析短暂动作的同步电池响应。
- 实验性分组边界、真实位置、温度含义、换算和不同市场/固件适配仍待独立验证。
- 转速、驱动扭矩、挡位、压缩机状态未映射；不能以电池功率代替电机机械功率。
- 没有 DBC 解码实现、CAN FD、跨机器数据导入 UI、动作标记图表叠加或多用户认证。
- 回放当前依赖本地索引与数据文件；备份需同时保存，只有一个 NDJSON 文件不能从 UI 自动导入。

## 下一阶段候选

先稳定串口连接与配置的动态调节，减少为加载代码而重连。随后寻找有来源的转速/扭矩定义，逐项验证 ECU 地址、DID、大小端、倍率、无效值及符号，再加入白名单；不做盲扫。可继续完善标记叠加、离线导入和更长时段回放。

连接成功后，主动断开或重启占用设备的后端须经操作者明确同意。故障中断应如实报告，不自动恢复。
