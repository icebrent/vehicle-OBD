# 物理量与证据

原始 CAN 和物理量解码分离。没有车型/DBC 时仍可完整显示原始报文；未知字节不自动命名为车速、转速或 SOC。

通用路径为 Transport → 原始帧存储 → Decoder → 带单位/时间/质量/来源的信号。未来可接 cantools；目前没有 DBC 解码实现。定义需记录起始位、大小端、符号、缩放、偏移、无效值、多路复用、版本与许可，并通过独立参考验证。

## 当前实验性 DID

`backend/protocols/byd_did.py` 提供独立固定白名单，不从车型选择自动触发：地址 7E7 → 7EF，0005 SOC、0008 电压、0009 电流、0032 温度；可选 10 组电压极值与温度 A/B。所有响应只接受匹配的 ISO-TP 单帧。分组边界、位置与换算仍属候选。

来源：[公开 BYD 列表](https://github.com/loryanstrant/BYD-PID-list)、[WiCAN 配置](https://github.com/meatpiHQ/wican-fw/blob/main/vehicle_profiles.json)。不同 ECU 的相同 DID 不代表同一物理量，其他车型/市场/固件成功不代表本车成功。公开代码与测试不包含私人日志。

电池功率 = 顺序读取的电压 × 电流 / 1000，样本相隔超过 15 秒不派生；这不是同步测量，也不是电机机械功率。电流正负方向尚需车辆验证，倒车不应据此强制显示负电流。

转速、驱动扭矩、挡位、空调压缩机状态目前没有已接入且可信的映射。需从有来源的请求/响应与参考值对照中逐项确认；不盲扫、不将发动机 RPM 或未知响应冒充驱动电机信号。
