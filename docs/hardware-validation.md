# 硬件验证步骤

先用台架验证解析、过滤和静默接收，再由操作者决定是否在停放车辆上使用。不要将候选配置视为所有车型的已知参数。

1. 关闭冲突应用，核对供电与 Windows 出站 COM 端口，人工选择速率。`start-hardware.ps1` 只开放入口，不自动连接或保存。
2. 使用独立 CAN 节点生成已知 11/29-bit 帧（含低数值扩展 ID）、DLC 0/1/4/8 与 RTR。本项目不生成测试 CAN 数据帧。
3. 连接 ATI / STDI，确认配置返回正常；不支持或超时即停止，不自动探测速率。
4. 被动 STM 16 测试由独立分析仪验证没有 ACK、数据帧或 flow control，核对混合 ID 过滤覆盖和实际 RTR 输出。只收到了部分身份不代表全部总线可见。
5. 手动保存短记录，完成后核对原始 payload、数量和离线回放。时间仅代表 PC 接收，不测硬件级延迟。
6. 经操作者同意再测试停止、重连、蓝牙掉线和 BUFFER FULL。不要在尚需保持的链路上擅自进行故障注入。
7. 诊断只在操作者明确选择 DID 模式后运行固定请求。独立核对响应与参考仪表；无有效响应不自动尝试其他 ECU 或 DID。
8. 物理量验证先静止记录，再由操作者自行决定简单场景。驾驶者不操作界面；动作标记是备注，不能替代挡位等真实信号。

MX+ 不是已认证的无损 CAN 记录仪，本项目不支持 CAN FD。未定义的转速/扭矩不得通过未知字节或通用发动机 PID 冒充。
